# Архитектура и алгоритмы

## Три независимых режима

1. **dense** — компактная раскладка по реальным контурам. Конструктивный bottom-left/skyline-like перебор кандидатных позиций; проверка действительных расстояний Shapely. Не претендует на globally-optimal nesting.
2. **uniform** — сначала плотная раскладка, затем локальные смещения на шагах 1,0 / 0,5 / 0,25 мм для снижения штрафа по зазорам 3 ближайших соседей и площади bounding box. Не гарантирует полностью одинаковые зазоры.
3. **ordered** — уважает порядок объектов в экспортированном выделении, размещая по контурам с контролем зазоров. Для стабильного пользовательского порядка заранее расположите выделение/список нужным образом.

## Дополнительная функция: группы одинаковых эмблем разных размеров

Флаг `--families named` собирает по именам `Ultramarines__3mm`, `Ultramarines__5.5mm`, `Ultramarines__7mm`. Флаг `--families auto` дополнительно сравнивает нормализованные силуэты в растровом отпечатке 28×28 и сохраняет согласованные имена. Флаг независим от трёх режимов.

Для группы строится **временный вычислительный кластер** с элементами от меньшего к большему; исходный AI **не объединяется и не меняется**, лишь вычисляются координаты участников. Кластеры размещаются как единые геометрические объекты, что физически держит ряд размеров вместе. При слишком длинном наборе группа переносится на следующую строку внутри своего блока.

Результат содержит `family` каждого объекта; автоматическая классификация требует ручной проверки до серийной гравировки.

## Дополнение v0.2: четыре независимых края и line-wise flow

Вместо единого поля `margin` теперь используется четыре значения `left/top/right/bottom` (мм). Общий `--margin` сохранён для обратной совместимости. Геометрические ограничения в `contained()` и `candidate_positions()` проверяют каждую сторону отдельно, а `edge_clearances_mm` возвращает реальные расстояния до краёв в итоговом макете. Красная пунктирная рамка на маршрутном SVG обозначает запретную к размещению полосу по краям.

Опция `--flow free|rows|columns` влияет на **эвристику физического размещения**: свободное компактное, построчное или поколоночное укладывание. Это не команды для лазера. Построчный вариант может **увеличить** занятую площадь или ухудшить равномерность, поэтому всегда нужно сравнивать с `free`.

Опция `--travel-order source|nearest|rows|columns` влияет только на **расчётный обход** итоговых центров объектов. Блок `laser_plan` хранит последовательность и расстояния от условного старта к центру следующей эмблемы. `--travel-svg` рисует условные перемещения с выключенным лазером, `--travel-csv` сохраняет шаги. Nearest + ограниченный 2-opt приближает короткий обход; ряды/столбцы реализуют змейку. Ни изменение порядка объектов в исходном AI, ни настоящие лазерные ходы в EZCAD/LightBurn пока не выполняются.

**Ограничение прокси:** центры залитых силуэтов — не реальные точки включения луча. Galvo-рецепт (контуры, hatch/fill, частота, стратегия проходов и совместимость с конкретным ПО) задаётся отдельно и может полностью менять порядок и длину реальных ходов. Экономия по `travel_total_mm` не равнозначна экономии времени на станке.

## JSON протокол

`export_selection.jsx` экспортирует контура в миллиметрах относительно центра bounding box выделенного объекта; `kiki-layout` возвращает абсолютные центры относительно верхнего левого угла **активного монтажного стола**. JSX-импорт перемещает и поворачивает оригинальные объекты; вершины и масштаб не меняются. Экспорт/импорт связываются индексами выделения и именем документа.

Отступы измеряются до **приближённой видимой области**: заливка + геометрическая оболочка открытых/закрытых штрихов с толщиной. Это не точный лазерный контур и требует аудита перед производством. У составных контуров even-odd формирует отверстия; nonzero требует расширенного движка.

## Метрические проверки

- `min_clearance_mm`: минимальный попарный контурный зазор по всей пластине;
- `nearest_3_mean_mm`: среднее расстояние до трёх ближайших соседей;
- `nearest_3_stdev_mm`: разброс расстояний;
- `silhouette_area_mm2`: сумма фактических площадей фигур;
- `occupied_bbox_mm2`: bounding box итоговой композиции;
- `within_margins`: контроль выхода за границы;
- `edge_clearances_mm`: фактические четыре отступа;
- `travel_proxy`: условная суммарная длина обхода, длина самого длинного перехода, число длинных переходов по указанному порогу.

Нужны сравнения по одинаковой пластине в разных режимах, без догматичного выбора «лучшего»: высокая плотность и равномерность зазоров могут конфликтовать.

## Дальнейшие инженерные улучшения

- Exact no-fit polygons + Minkowski sums, индексирование геометрии (STRtree), global simulated annealing, проверка случаев >300 объектов;
- геометрия с nonzero fill rule, stroke outlines, поддержка compound/appearance;
- надёжные UUID и атомарная операция экспорта/импорта с подтверждением идентичности;
- предпросмотр и интерактивная панель UXP после появления production API Illustrator;
- сравнительный снимок «до/после», генерация QA-отчёта по зазорам и технологическим ограничениям.

## v0.5 Core Beta — объектные ограничения и пресеты

`constraints.json` (в папке одного экспорта) содержит имя `.ai`, исходные границы
каждого выбранного объекта и индивидуальные ограничения. Перед расчётом
`constraints.validate_constraints` проверяет совпадение документа и границ;
`engine.layout` размещает закреплённые фигуры как неизменяемые препятствия.
Расчётный `result_test.json` по-прежнему проверяется в Illustrator перед
применением. Общие пресеты сохраняются отдельно и не включают объекты.

Это не замена ещё не завершённого CEP Unified Interface: текущая CEP-панель
по-прежнему вызывает отдельное окно Python для настройки и расчёта. После
готовности единой панели UI сможет вызывать тот же `gui_jobs.calculate` без
изменения правил геометрии. UXP, когда станет доступным в Illustrator, должен
заменить CEP-адаптер, а не Python-движок.

## v0.6 Advanced Nesting Beta

Добавлен внешний multi-start слой вокруг прежнего валидируемого размещения. Первый проход всегда совпадает с базой v0.5.2, следующие используют воспроизводимые вариации порядка единиц размещения; для Ordered изменяются только предпочтения размещения, но не порядок. Результат выбирается только после полного попарного контроля минимального зазора, проверки всех краёв и индивидуальных ограничений. Отдельные checkpoint-файлы не пригодны для команды Apply.

Временной лимит **soft**, а не real-time hard deadline. Полный NFP отсутствует: включаемые отдельно vertex/offset boundary anchors — это эвристика кандидатов. По умолчанию отключена до расширенных тестов с вогнутыми геометриями и отверстиями. См. `docs/v0.6-advanced-nesting.md`.
