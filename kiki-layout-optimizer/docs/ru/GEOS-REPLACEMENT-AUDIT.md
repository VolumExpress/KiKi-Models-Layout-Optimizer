# Проверка заменяемости GEOS для v0.7.2 Beta

Это **дополнительное техническое испытание**, а не юридическое заключение.
Публикуемые Windows Setup, Portable ZIP и macOS DMG не модифицируются.

## Метод

1. Workflow `GEOS LGPL technical replacement audit` собирает точную конфигурацию KiKi с PyInstaller `--onedir` на Windows и macOS.
2. Загружает **официальный** исходный архив GEOS 3.14.1, сверяет фиксированный SHA-256 `3c20919cda9a505db07b5216baa980bacdaa0702da715b43f176fb07eff7e716` и версию в `Version.txt`.
3. Пересобирает независимые динамические библиотеки GEOS с CMake на соответствующей ОС. CMake и компилятор нужны **только на GitHub runner**, не пользователю KiKi.
4. Подменяет GEOS в **временной копии** Portable, учитывая хешированные DLL Shapely на Windows и повторяющиеся dylib на macOS.
5. Выполняет реальный расчёт синтетической пластины с пересобранной GEOS и проверяет, что контрольные суммы заменённых библиотек отличаются от исходных.
6. Делает отрицательный контроль: повреждает все C API библиотеки GEOS во второй копии. Расчёт обязан завершиться ошибкой. Это помогает обнаружить загрузку библиотеки из другого места.

Если обе платформы дадут `success`, скачайте артефакты `KiKi-GEOS-replacement-audit-windows` и `...-macos`, изучите `report.json` и прикрепите отчёты к журналу приёмки релиза.

## Ограничения

- Успешный тест показывает способность программы работать с **пересобранной совместимой** GEOS на протестированной архитектуре, но не подтверждает возможность произвольных несовместимых изменений.
- Наличие upstream-архива само по себе не доказывает полную идентичность исходников и сборочных опций библиотек из колёс Shapely. Это нужно проверить по provenance источника wheel, а при изменениях — предоставить соответствующие исходники/патчи.
- Условия LGPL-2.1, включая уведомления, возможность использования модифицированной совместимой библиотеки и предоставление соответствующих исходников, оцениваются отдельно. Не объявляйте результат `LGPL compliant` только по зелёному CI.
- Работа расширения Adobe Illustrator на macOS не проверена, даже если технический тест GEOS завершился успешно.

Важно: после добавления этого workflow в `main` потребуется **повторить финальную сборку из нового коммита** и обновить все вложения черновика Release, если тег должен строго совпадать с кодом, из которого собраны установщики.
